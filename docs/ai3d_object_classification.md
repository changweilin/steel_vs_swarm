# AI3D 物件分類、拆件與功能替換準則

機器可讀的唯一真相位於 `tools/ai3d/object_classification_policy.mjs`。本文件只說明判斷順序，
不另列第二份類型或角色名冊。

## 判斷順序

1. 先判斷物件「在現實中做什麼」，再判斷它「看起來像什麼」。建築按主要用途、船與載具按任務、
   樹按生長結構、岩體按地質形成分類。照片風格、顏色、輪廓與 primitive 類型都不是類別依據。
2. 同一張照片有多個獨立物件時，以 YOLO26 的穩定 target id 逐個分類；母照片只保存共同來源關係。
   YOLO26 沒有可用類別時保留全幅單一 target，不臆造偵測證據。
3. 拆件以現實功能與接合介面為界。具有獨立功能、接點、運動、碰撞、材料或失效模式者必須拆開；
   同一製造件上的折面、陰影、反光與裝飾線不得假拆成零件。
4. 每個零件必須標註功能角色、安裝介面、運動類型、負載、工作介質、左右手性、材料與語意配色槽。
   看得到但無法判定功能的細節標為 `unresolved_detail`，不得因此取得替換資格。
5. 缺少應有的功能零件時，分類列必須記錄 `decompositionStatus: "needs_decomposition"` 與
   `missingFunctionalParts`；生成模型只補這些具名功能，不按外觀任意切碎。

## 替換資格

零件替換採 fail-closed。物件用途先通過，再比對零件功能、安裝介面、運動、負載、介質、手性、材料、
配色槽與安裝點數。任何一欄缺失或不同即不可自動替換。尺寸只負責確認能否裝進目標槽，不可把外形
相似當成資格。

配色也按語意槽逐欄替換。結構色只能換結構色，玻璃、燈號、安全標記、工作面、植被與風化層各自
隔離；軍民標記、航海導航、宗教象徵與法定安全標記不得跨域搬用。色差、主色接近或整張色票相似
一律不構成相容證據。

主結構、權威碰撞、LOS、地面接觸或遊戲語意不同時，不論外觀多相似都不可互換。幾何相似度仍可
用於渲染批次與預覽排序，但必須在功能相容性閘門之後，且不得擴大候選集合。

## 分類產物

每個家族各有一份 `tools/ai3d/object_classifications/<family>.json`。一列對應一張直屬原始照片，並以
`source.corpus + source.image` 建立穩定身份；產生清單時，同列附上該照片的 YOLO26 feature 及全部
target crop、mask、depth 路徑，因此原圖與衍生證據永遠一併歸類，不靠搬動檔案維持關係。來源檔
保留原位，避免破壞來源帳與人眼判決鍵；照片含多個可獨立建模 target 時，零件列須保留各 target 的
現實功能，幾何管線仍用 YOLO26 target id 個別生成。

兩個 corpus 的 YOLO26 feature、crop、mask、depth、v6 target id 與穩定鍵都必須帶 corpus id。直屬
未分類來源若沒有 Luna 功能分類，v6 ingest 會 fail-closed；有分類時，生成與獨立複核都必須讀入完整
功能拆件表，並把 `missingFunctionalParts` 補成獨立幾何零件後才可入庫。
