### 3.1 洞口打洞漏刪「跨越走廊」的三角形

**症狀**:明隧道端部(= 出入口)斷面裡卡著一楔地形 —— 洞內橫向射線在離中心線 7.1~7.8m、路面上 2~4.4m 處打到地形。對應使用者先前回報的「洞內卡著不明石頭」。

**根因**:`terrain.js punchPortalHoles` 的走廊判定是「**任一頂點**落在走廊內」。地形格 ~8.3m、對角 ~11.7m,而走廊縱向只有 0.5m 與 `depth` 兩道界 ⇒ 洞口與明隧道段端點附近常出現「三個頂點全在走廊外(側向 > hw 或縱向越界)、整片卻橫切斷面」的三角形。頂點法漏刪它,而且該片不會進 `rims` ⇒ collar 也補不到。

**修法**:判定改成「三角形(XZ 投影)× 走廊矩形**重疊**」(`triBore`,2D SAT:走廊兩軸 + 三角形三邊法線)。實例點仍走 `inBore`(InstancedMesh 縮零本來就是點語意)。垂直三條界(路面下不刪 / 天花上不刪 / 走廊外不刪)一字未動。

**驗證**:
- `audit_open_tunnel.mjs` **Ⅵ**(新增,執行 `punchPortalHoles` 原文):跨越三角形 MUST 刪、走廊內 MUST 刪、走廊外/路面下/天花上 MUST 留、洞緣 MUST 進 `rims`。
- **反向驗證**:把判定改回「任一頂點」→ Ⅵ 第一條紅字(其餘全綠),證明這條斷言真的在管這件事。
- 多視角掃描:明隧道殘留 3 → **0**;山體隧道與地下道**五項數字逐項不變**(= 沒有過度打洞)。

### 3.2 洞口淨空只到洞口平面 —— 走廊往洞外延一格

**症狀**(使用者回報第 6、7 張圖):洞內往外看,洞口內側左右各浮著幾片土色薄片,幾乎壓在路面上方;
洞口「沒有淨空」。射線辨識(`--debug` 的命中特徵)確認那是**地被層拼圖**(`vertexColors` + `map` 的大 Mesh),
不是地形高度場,也不是 collar。

**根因**:打洞走廊的縱向界是 `lz ∈ [−depth, −0.5]` —— 只涵蓋洞口平面**內側**。洞口外那一格(地形格 ~8.3m)
的切面上仍攤著地被與地形殘片,它們斜插進洞口斷面。

**修法**:門洞的 bore 帶 `out = TUN.MOUTH_OUT`(8m ≈ 一格),走廊往洞外延伸;`galBores`(明隧道洞內段)
維持 0 —— 它的「外」是隔壁小段。**垂直三條界一字未動** ⇒ 路塹底、圍裙、山體照樣不刪。

### 3.3 洞體內外的道路寬度不同 —— 避車道邊帶同步漸縮

**症狀**(使用者回報第 4 張圖):明隧道洞內外的道路沒接好、寬度不同。

**根因**:結構內的斷面是「中央車道(`carriageHw`)+ 兩側避車道邊帶(到 `strucHw`)」,而洞口外的
`ROAD_FLARE_M` 漸縮帶**只鋪柏油** ⇒ 出洞那 12m 變成一片全寬柏油、邊帶憑空消失,斷面在洞口跳一階。

**修法**:邊帶跟著楔形吃**同一個 `fhw`**(MUST NOT 自己再算一次半寬),外緣收到零、車道緣全程不動 ⇒
洞內外同一個斷面。純視覺,通行寬唯一縫仍是 `strucHw`。

### 3.4 開挖邊緣的地物懸在路塹上方

**根因**:走廊地物淨空半徑 `hw + 4` 窄於開挖足跡(`carveTunnels` 山體斜壁 `hw+7`、引道緣石帶 `hw+UND.COPE`)
⇒ 開挖邊緣仍會生地被特徵拼圖與擺件,它們以單一取樣高擺位,挖空後就懸在路塹上方。

**修法**:結構段(`kind === 'tun'`)改吃 `hw + STRUCT_CLEAR_PAD`(=8);橋維持 `hw + 4`(橋下淨空語意不同)。

**共同驗證**:`audit_road_joint.mjs` 74 綠(Ⅳ 新增邊帶漸縮直測:外緣收到零、與楔形同一條 `fhw`、車道緣不漂、
差額 < `AVOID_MIN` 同進退;**反向驗證**把邊帶外緣改回固定 `hw` → 兩條紅字)、`audit_open_tunnel` 113 綠、
`audit_underpass` 132 綠、`audit_terrain_ray` / `audit_layer_block` / `audit_road_bed` / `audit_slope_move` 全綠;
`npm test` 全通過;`npm run bal` 四不變式通過。

# 第二輪:真實 OSM 圖資(2026-08-01)

## 5.0 這一輪為什麼跑得起來

第一輪的三條沙箱限制(Overpass / Esri / 真瀏覽器)在**開發機**上都不成立:

- Overpass 三個鏡像實測皆可達 —— 主站與 kumi 需要帶 `User-Agent`(不帶會拿到 406 / 429,看起來像「連不出去」,其實只是被擋標頭)。
- Playwright 走全域安裝(`npm i -g playwright` + `playwright install chromium`),`tools/pw.mjs` 以 `NODE_PATH` 指到全域 `node_modules` 即可解析。**MUST NOT** 寫進 `package.json`(§1 技術棧規則)。
- three 走 CDN(本機無 `node_modules/three`,`shot_tunnels` 的本機攔截自動略過)。

⚠ **圖資逐局浮動仍在**:同一場地連跑,Overpass 偶爾回空/截斷 ⇒ 該局整張圖沒有結構(實測金龍隧道一次 `covSegs=0`、燕子口一次 `門洞 0 / 小段 0`)。判讀 `--live` 結果前 MUST 先看那行「小段 N」,N=0 的一局不是「結構消失」而是「這局沒拿到圖資」。

- **五項掃描**:斷面地形殘留 0 / 1068、由上而下看穿 0 / 5395 —— 第一輪的打洞與 collar 在真圖資上同樣乾淨。
- **斷面遮擋 2(修正後)**:兩筆都落在門洞正中心(`dy=1`、`dist` 7.2 / 7.4 對 `hw=8`),射線特徵 = 非實例、無 vertexColors/無貼圖、204 頂點的灰色構件 ⇒ **門面框本身**把斷面收窄 0.8m,不是侵入物。掃描門檻是 `hw − 0.6`,門面框天生就在門檻內側 —— 這兩筆是**掃描的已知偽陽**,不是缺陷。

## 5.2 修正 5-A:神木腳印淨空只問中心格

**症狀**:洞內斷面卡著大型物體(空拍可見隧道線正上方就是一片神木林)。

**根因**:`placeGiantGroves` 的淨空檢查是 `blocked.has(cellKey(gx, gz))` —— **只問中心那一格**。淨空網格 `CELL` 只有 10m,而神木幹半徑可 >10m ⇒ 中心落在走廊淨空外一格、樹身照樣橫插進洞內斷面。巨岩 `placeMegaliths` 一向走 `areaFree(r + 6)` 掃整盤,神木漏了這一關。

**修法**:腳印半徑具名 `foot = def.r * s * 1.6`(基部喇叭口 + 板根鰭)成為**單一縫**,落底 `sinkBaseY` 與淨空 `areaFree` 同吃;淘汰檢查移到體格 `s` 抽樣**之後**(§2.3 抽樣紀律 —— `foot` 要有 `s` 才算得出來)。

**驗證**:`audit_open_tunnel.mjs` **Ⅲ-d**(4 項 + 抽樣序 1 項);反向驗證改回「只問中心格」→ Ⅲ-d 三條紅字。

> 註:這一刀**沒有**改掉 §5.4 那個看起來像樹幹的東西(見下),但它是真缺陷 —— 巨幹橫插洞內是一定會發生的事,只是金龍這一局剛好沒被 9m 間距的掃描抓到。

## 5.3 修正 5-B:走廊淨空半徑手寫,漏掉明隧道柱外淨空帶

**根因**:`STRUCT_CLEAR_PAD` 是**手寫的 8**,而開挖足跡有三道:山體斜壁 `hw+7`、引道緣石帶 `hw+UND.COPE`(8)、明隧道柱外淨空帶 `hw+TUN.GAL_CLEAR_W`(**9**)。最寬的那道沒被蓋到 ⇒ 簷口外緣留下 1m 寬的殘環,地物站在**已經被 `carveGalleryBands` 挖掉**的地面上 —— 這正是第一輪 §2.3 待決②「端部簷口外緣站著行道樹」。

**修法**:`STRUCT_CLEAR_PAD = Math.max(7, UND.COPE, TUN.GAL_CLEAR_W)` —— 推導,MUST NOT 手寫。橋維持 `hw+4`(橋下淨空語意不同)。

**驗證**:`audit_open_tunnel.mjs` **Ⅲ-c**(6 項:推導不手寫 + 逐道開挖足跡下界 + 消費端);反向驗證改回 `8` → 兩條紅字。**待決② 結案。**

## 5.4 修正 5-C:別條地表道路的路面緞帶橫在洞內斷面 ← 本輪主角

**症狀**:洞體中間往前看,一片**深褐色斜板**自路面竄到天花板,肉眼像一根倒下的巨木樹幹;四個門洞裡有兩個也看得到同款。這就是使用者長期回報的「洞內卡著不明物體」剩下的那一件。

**辨識**(射線打到什麼,逐項特徵):非實例 mesh、`vertexColors` + 貼圖 + **`polygonOffset`**、5148 頂點、材質色 `0x77603f` = `roadColor('green', main=false)`、包圍盒橫跨整張圖 —— 全部指向**道路緞帶的合批桶**(綠地小馬路那一桶)。落點在洞底上方 1.6m、離中心線 1.8m,深深在斷面裡。

**根因**:`punchPortalHoles` 刪的是**地形三角形 + 地被實例**;**路面緞帶是另一個 mesh,不在打洞範圍內**。而判成明隧道的地方,前提就是「地表落在洞底與頂板之間」—— 山坡上那條路的緞帶於是整片橫在洞內。合成 way 看不到這件事,因為合成場景裡只有那一條路。

**修法**:貼地路段的路面緞帶與標線,落進**別條路的洞內斷面**就不成面。判定 `inTunBore` 吃 `markGradeCorridors` 回傳的**同一份走廊清單**(新增頂板底面 `cy = tunFloorAt + TUN.CLEAR`,推導不手寫)—— MUST NOT 在 `buildRoads` 另算一份隧道剖面。三條紀律:

- 只作用在**貼地段**(`!strc && !brg`):結構自身的路面與橋面就該在那裡。
- **自頂板上方通過一律放行**:路鋪在洞頂的山坡上是合法的,那才是隧道的意義。
- 頂點照推、只是**不成面**:序號不變 ⇒ 佈局與下游(漸縮帶頂點基底)逐位元不漂。

三個消費端全掛:路面緞帶 `idx`、`emitLine`(縱向實線)、`dashLine`(白虛線)。

**驗證**:`audit_open_tunnel.mjs` **Ⅲ-e**(15 項:走廊帶 `cy` 且推導、兩處呼叫端都傳走廊清單、判定只有一份、三消費端全掛、`!strc && !brg`,外加抽 `inTunBore` 原文的 5 項行為直測 —— 頂板之上放行 / 斷面之內攔下 / 走廊外放行 / 內側邊界攔下 / 端點外延長線夾制);反向驗證拿掉緞帶那道閘 + 放寬頂板界 → 兩條紅字。
**實測**:斷面遮擋 3 → 2(剩下兩筆是 §5.1 的門面框偽陽),洞體中間與門洞的配圖裡斜板消失,其餘四項掃描逐項不變(= 沒有誤刪合法路面)。

> 一點誠實揭露:端對端那一局跑的是**加上全圖包圍盒早退之前**的版本。早退是純加速(全域包圍盒外必然也在每一段的 `hw` 之外、`y > 全域最大 cy` 必然也大於個別 `cy`),由 Ⅲ-e 的 5 項行為直測 + 1 項靜態斷言釘住,未再跑一次 25 分鐘的出圖。
