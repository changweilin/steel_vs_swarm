## 2. 逐結構

### 2.1 山體隧道

- **洞外向內看**:額牆 + 兩翼擋土牆 + 黃黑警示條紋齊全;路面標線連續進洞,洞內天花燈往深處延伸,遠端見天光。無舊版「洞口一片黑板」。
- **洞內向外看**:出洞見天空與景物,無黑牆;天花/橫樑/燈在仰視圖完整。
- **洞體中間**:地板、兩側牆、天花四面封閉,半球取樣**見天 0**。
- **量化**:斷面地形殘留 0、斷面遮擋 0、由上而下看穿 0。洞口見天殘值 3 / 9 是門面邊緣掠射,配圖確認不是破口。
- **設計行為(非缺陷)**:41 個小段中近洞口 9 段被 `tunnelWallProfile` 判為明隧道 ⇒ 從洞口斜看會**透過柱列見天**。這是「側向土牆藏不住結構就改明隧道」的既定判定,不是漏光。
- **場地相依觀察**:結構通行寬(≥ `PASS_W`/2)與洞外真實路寬的落差由 `ROAD_FLARE_M` 漸縮帶收;當洞口外 12m 的地表低於結構路面逾 3m(臨崖側)時,漸縮帶依「寧缺勿錯」跳過 ⇒ 洞口外緣是一道硬邊。合成 way 的洞口正落在陡坡上放大了這個情形,**真圖資場地需複驗**再決定是否要放寬跳過條件。

### 2.2 地下道

- **五項掃描全 0**(含洞口見天 0/585、0/567),是三者中最乾淨的。
- **洞外向內看**:垂直路塹 + 擋土牆 + 緣石帶 + 街燈;路面下沉剖面連續,無錯層。
- **洞內向外看**:兩端出入口只在道路頭尾,側壁封閉 —— 與 A29「側面 MUST NOT 留可通行開挖斜坡」相符。
- 觀察:路塹底面在通行寬與塗裝寬之間的差額帶是裸地(避車道邊帶語意),與隧道內同款,一致。

### 2.3 明隧道

- **洞體中間**:靠山側整面牆、臨谷側矮牆 + 連續柱列 + 外露頂板 + 簷口封邊,路面標線與天花燈完整;柱間見天 23~31/240 = **設計如此**(柱間透明可見可穿透,兩端同判)。
- **兩端**:road 進出連續、頂板/牆帶收邊,街燈與護欄接得上。
- **修正**:端部斷面殘留地形楔 3 → 0(§3)。
- **待決①(本次未動)**:整段覆蓋的明隧道**兩端不立門洞** —— `biomes.js` 洞口條件是 `c0 >= 4 / c1 <= total - 4`(覆蓋貼齊 run 端側沒有引道就不立門)。結果是端面只有頂板與牆帶收邊,沒有額牆/翼牆。目視可接受,但與「出入口」的直覺有落差。若要補立門面,MUST 同步檢查 `userData.portals` 數量不變式(金龍恆 8 座)與 `TUN.PORTAL_MAX` 預算,屬另一件事。
- **待決②**:端部簷口外緣站著行道樹(走廊淨空半徑 `hw + 4` 之外、柱外淨空帶 `GAL_CLEAR_W` 之內)。掃描判定「斷面內無遮擋」成立,但從洞內斜看會看到樹幹貼著柱列。要不要把明隧道段的淨空半徑放寬到 `hw + GAL_CLEAR_W`,建議在真圖資場地上決定。

### 3.1 洞口打洞漏刪「跨越走廊」的三角形

**症狀**:明隧道端部(= 出入口)斷面裡卡著一楔地形 —— 洞內橫向射線在離中心線 7.1~7.8m、路面上 2~4.4m 處打到地形。對應使用者先前回報的「洞內卡著不明石頭」。

**根因**:`terrain.js punchPortalHoles` 的走廊判定是「**任一頂點**落在走廊內」。地形格 ~8.3m、對角 ~11.7m,而走廊縱向只有 0.5m 與 `depth` 兩道界 ⇒ 洞口與明隧道段端點附近常出現「三個頂點全在走廊外(側向 > hw 或縱向越界)、整片卻橫切斷面」的三角形。頂點法漏刪它,而且該片不會進 `rims` ⇒ collar 也補不到。

**修法**:判定改成「三角形(XZ 投影)× 走廊矩形**重疊**」(`triBore`,2D SAT:走廊兩軸 + 三角形三邊法線)。實例點仍走 `inBore`(InstancedMesh 縮零本來就是點語意)。垂直三條界(路面下不刪 / 天花上不刪 / 走廊外不刪)一字未動。

**驗證**:
- `audit_open_tunnel.mjs` **Ⅵ**(新增,執行 `punchPortalHoles` 原文):跨越三角形 MUST 刪、走廊內 MUST 刪、走廊外/路面下/天花上 MUST 留、洞緣 MUST 進 `rims`。
- **反向驗證**:把判定改回「任一頂點」→ Ⅵ 第一條紅字(其餘全綠),證明這條斷言真的在管這件事。
- 多視角掃描:明隧道殘留 3 → **0**;山體隧道與地下道**五項數字逐項不變**(= 沒有過度打洞)。

### 3.2 洞口淨空只到洞口平面 —— 走廊往洞外延一格

**症狀**(使用者回報第 6、7 張圖):洞內往外看,洞口內側左右各浮著幾片土色薄片,幾乎壓在路面上方;
洞口「沒有淨空」。射線辨識(`--debug` 的命中特徵)確認那是**地被層拼圖**(`vertexColors` + `map` 的大 Mesh),
不是地形高度場,也不是 collar。

**根因**:打洞走廊的縱向界是 `lz ∈ [−depth, −0.5]` —— 只涵蓋洞口平面**內側**。洞口外那一格(地形格 ~8.3m)
的切面上仍攤著地被與地形殘片,它們斜插進洞口斷面。

**修法**:門洞的 bore 帶 `out = TUN.MOUTH_OUT`(8m ≈ 一格),走廊往洞外延伸;`galBores`(明隧道洞內段)
維持 0 —— 它的「外」是隔壁小段。**垂直三條界一字未動** ⇒ 路塹底、圍裙、山體照樣不刪。

### 3.3 洞體內外的道路寬度不同 —— 避車道邊帶同步漸縮

**症狀**(使用者回報第 4 張圖):明隧道洞內外的道路沒接好、寬度不同。

**根因**:結構內的斷面是「中央車道(`carriageHw`)+ 兩側避車道邊帶(到 `strucHw`)」,而洞口外的
`ROAD_FLARE_M` 漸縮帶**只鋪柏油** ⇒ 出洞那 12m 變成一片全寬柏油、邊帶憑空消失,斷面在洞口跳一階。

**修法**:邊帶跟著楔形吃**同一個 `fhw`**(MUST NOT 自己再算一次半寬),外緣收到零、車道緣全程不動 ⇒
洞內外同一個斷面。純視覺,通行寬唯一縫仍是 `strucHw`。

### 3.4 開挖邊緣的地物懸在路塹上方

**根因**:走廊地物淨空半徑 `hw + 4` 窄於開挖足跡(`carveTunnels` 山體斜壁 `hw+7`、引道緣石帶 `hw+UND.COPE`)
⇒ 開挖邊緣仍會生地被特徵拼圖與擺件,它們以單一取樣高擺位,挖空後就懸在路塹上方。

**修法**:結構段(`kind === 'tun'`)改吃 `hw + STRUCT_CLEAR_PAD`(=8);橋維持 `hw + 4`(橋下淨空語意不同)。

**共同驗證**:`audit_road_joint.mjs` 74 綠(Ⅳ 新增邊帶漸縮直測:外緣收到零、與楔形同一條 `fhw`、車道緣不漂、
差額 < `AVOID_MIN` 同進退;**反向驗證**把邊帶外緣改回固定 `hw` → 兩條紅字)、`audit_open_tunnel` 113 綠、
`audit_underpass` 132 綠、`audit_terrain_ray` / `audit_layer_block` / `audit_road_bed` / `audit_slope_move` 全綠;
`npm test` 全通過;`npm run bal` 四不變式通過。
