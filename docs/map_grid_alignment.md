## 1. 使用者定案(原句;所有取捨的上游)

> 「處理圖資時先找出地圖上下左右對準哪一個方向時,可以對齊最多的大馬路組成正交網格,接著將
> 所有道路量化成 16 個方向,同時盡可能避免讓道路變成鋸齒,這樣道路拼圖可以透過這 16 個方向
> 簡化並無縫準確貼合對齊,建築也更容易對齊排列。」
>
> 「圖資儲存在開房者,再由開房者透過 server 傳給入房者?」

追問後定案:**真的旋轉整張地圖**(不是只拿 θ 當 16 方向的錨);量化對象**只有 `osmRoads`**
(鐵路/兵線/建物輪廓皆不動)。

## 2. 已排除的選項(**不要重新提案**)

| 選項 | 排除理由 |
|---|---|
| 只把 θ 當 16 方向的錨、世界不轉 | 使用者選了「真的旋轉整張地圖」 |
| θ 在**建圖期**由各客戶端自己算 | 那是每台各跑一次的,而 `scheduleOsmRetry` 的存在就證明 Overpass 被限流是常態 ⇒ A 抓到 −29°、B 拿 0°,兩台的世界差 29°。圖資 miss 只讓那台少幾座橋(局部);θ miss 是所有座標對不上(全域)|
| 用**已在手上的兵線**估 θ(零網路) | 58 組對比烘焙值:p90 **16.1°**、max **44.0°**,落在半格內只有 79%;還會**同一張圖隨人數轉不同角度**(shibuya L1/L3/L5 = −6.3/27.8/29.7°)|
| 事後把短方向段併進鄰段來去鋸齒 | 階梯被併回單一方向 ⇒ 長度重解退化成「兩錨點之間拉直」= 等於沒量化。拿掉併段後誤差 p90 5.9° → 0.5°,而直段均長只從 122m 降到 86m。**已成 A42 ⑥ 禁令** |
| 不設位移上限、把路整條吸到鄰格 | 卡在格界(11.25°)的 1.5km 直路尾端甩出 **518m**,那條路就此離開衛星底圖、離開已整平的路基、離開自己那條兵線 |
| 自訂地圖的 θ 在 **mapSelect 掃描期**量 | 掃描時 `center` 還沒定案(它是錨點與**所選候選點**的中點)。改在「存入最愛」那次量:手動地圖一定要存最愛才開得了房 ⇒ 涵蓋 100%,且輸出直接進 battleConfig |
| 中繼 payload 降到 6 位小數(可砍半)| `DP = 7` = OSM 原生精度 ⇒ 淨化對真圖資是**恆等**;降到 6 位會讓「走中繼」與「逾時自己抓」建出兩張略不同的圖 —— 小到剛好測不出來,而破圖照樣發生。1.05MB / 2MiB,用不著省 |
| 中繼路網寫進入房者的 geocache | 房主 = 不可信輸入;持久化會污染這台機器**之後每一場**(含它自己開房那場)。代價只是下一場再等一次中繼,而中繼很快 |

## 3. 還沒驗(㋕ 真機 / 兩台機器)

離線與 ㋓ 都跑完了;剩下的是**單一客戶端永遠測不到**的。

- **中繼兩台同房** —— 一台開房一台入房,比對橋隧與建物逐項一致(壞掉的症狀是「你說的那座橋我
  這邊沒有」)。同場看「房主被限流、90 秒後補抓成功」:入房者要在**房間階段**自動重建成同一份。
  順帶看進度回饋 —— 房主整組失敗時狀態列要在地形建完那刻換成「等待房主的道路圖資…」;
  正常情況中繼早就到了,**一個字都不該多**(多出來 = 顯示時機寫錯邊)。
- **自訂地圖主方位走一次** —— 手動點選 → 存入最愛(多發一次 Overpass)→ toast 印出角度 →
  開房建圖真的轉了。離線只驗得到接線與紀律,驗不到「畫面真的轉了」。
- **看一張旋轉過的市區圖** —— manhattan 或 barcelona(主方位大,效果最明顯)。

**與本題無關的既有紅字**(已在 main 覆核,不要誤修):`audit_touch_layout` 667×375 橫式;
`audit_lane_grade_sep` 在此 worktree 缺 `tools/.osm_cache` 而 ENOENT。

## 4. 待觀察 / 獨立題目

- **`audit_traverse` 21 條既有紅字**(橋面中段不可達 / 橋下淨空 / taroko 隧道)。旋轉前是 26 條、
  種類一條沒變 ⇒ 稽核端的泛洪/夾制議題,不是遊戲破圖。成因見 `traverse-audit-baseline-reds`
  記憶與該支檔頭。**修它是獨立題目。**
- **舊的「我的最愛」維持 `rot = 0`**(刻意不追溯):要補就得在開戰畫面再加一次網路依賴,
  換來的只是舊存檔轉個角度。
- **中繼 payload 餘裕不厚**:5v5 密市區 1.05MB ⇒ `maxPayload` 1.9×、`MAX_BYTES` 1.6×,而 OSM
  只會長大。**下次動這一族 MUST 重跑 `tools/measure_osm_relay.mjs`**(查詢字串取自 `biomes.js`
  執行原文,不會靜默過期)。
- **`civicblvd` 的 `relief: 27`**:重烤那輪實測是 `null`(側翼幾乎全落在橋/洞段,那些要扣掉),
  而稽核對 `peakSide == null` 刻意不判(分不出「沒量到」與「量到就是沒有」)⇒ 舊值留著。
