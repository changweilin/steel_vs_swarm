# 啟動時生成與部署 3D 場景實體

## 剩餘工程舊配方整合與盤點（2026-09-20）

移除倒塌高架橋的實心方牆與石層配方，改為分段橋面、下承梁、路面及兩側護欄。各殘段共用剛體旋轉，再按整段包絡落地；不再將整片橋面誤作護欄。`fallenViaduct` 的目標段長為 10–16 m、交替傾角為 0.08–0.22 rad、板厚為包絡高 8–12%，均由局部種子生成。

油槽改由 `storageTankParts` 唯一生成；坡地群落、一般邊界本體與緩衝區共用落地基座、筒身及閉合錐頂。`storageTank` 的半徑為較短底邊 40–46%、筒身高度為包絡高 66–80%、錐頂高為 6–10%。坡地排列保留原有每格種子抽取次序，新增細節不推移鄰格種子。油槽仍屬工業邊界模組，未新增任意場內散布入口。

路障、河堤、海堤的 `wallParts` 預覽改用正式 `buildSlopeBoundary`，刪除舊方牆／垛口配方。斷面沿用 `SLOPE_BOUNDARIES`；端面尺寸不隨種子變動，以保持連續接縫，色差使用既有座標取樣。城牆保留有石層、垛口與城樓的既有模組。

視覺抽驗另發現通用海岸緩衝區會在無寒冷條件時抽到浮冰，已套用既有 `environmentAvailable` 氣候資格檢查；無合格水域散布物件時使用既有岩石備援。明確選取的冰山／浮冰邊界仍保留。

本輪視覺抽驗橋梁殘段、油槽群、路障、河堤及海堤的模組與邊界模式。新增 `test/environmentInfrastructure.mjs` 驗證 80 組種子的支撐接點、逐段落地、油槽接合與平地／正式斷面同源；緩衝區測試要求存在主體，避免因角色名稱改變而跳過接縫斷言。另通過 17,920 組包絡、1,200 組坡地接縫、216 組混合接縫、169 項世界邊界稽核、實際渲染與 358 項客戶端語法檢查。

## 海岸與水產舊配方替換（2026-09-20）

視覺檢查確認：舊消波塊的四支圓柱穿過同一球心，呈石球／交叉棒堆；蚵棚兩根長梁只有單側支柱；海上牧場直接複用蚵棚，沒有浮框與網底。刪除這些配方，沿用海岸（coastal）及水產（aquaculture）分類，分為以下三種結構。`searanch` 的顯示名稱改為「浮式養殖網箱」，與實際生成內容一致。

| 配方 | 種子參數與範圍 | 不隨種子改變的結構規則 |
| --- | --- | --- |
| 四腳消波塊（tetrapod／wetpods） | 目標間距 3.2–4.2 m、2–3 層、臂長 1.5–1.8 r、端部半徑 0.48–0.62 r、方位 0–2π | 四臂由中心向外，任兩軸內積 −1/3；臂根連到核心；逐塊按包絡落地，層間交錯咬合；r 由格距、高度、深度共同限制 |
| 固定蚵棚（oysterracks） | 目標柱跨 2.5–3.5 m、梁高 2–3.2 m、每跨 4–7 根橫桿、垂掛長度為梁高 55–80% | 每跨四柱落地，兩根長梁各有兩端支撐；橫桿承接三列蚵串；保持靜態 |
| 浮式養殖網箱（searanch） | 目標模組間距 7–10 m、網深 1.8–3.2 m、浮框截面 0.3–0.5 m、網格 4–7 跨 | 四邊浮框閉合，側網連到網底；浮框中心位於水線，網底在水下；同模組共用浮動樞紐 |

數值是低模美術參數，非工程或養殖操作規範；跨數先取整，再均分長度。各模組使用獨立種子，零共享亂數消耗。四款仍屬邊界／工程模組，透過 `linearEnvironmentParts` 同時供正式邊界與預覽使用，不加入任意場內散布。邊界碰撞尺寸與連續阻擋環沿用既有設定。

水線由描述子提供，正式動態渲染在群組根節點套用，避免只修正靜態零件而讓浮動網箱升回水面上方。預覽的獨立模組及邊界排列也依水陸分類選擇水面與水線偏移。

養殖邊界外側緩衝區改用同款網箱／蚵棚，移除通用布景抽到浮冰的錯配。規則網格排列會同步平移運動樞紐，並為每格的運動群組配置獨立識別碼，避免多格網箱或風機被合併到錯誤中心。

形態依據：[四腳消波塊產品說明](https://jayabeton.com/products/water-management/tetrapod)、[FAO 浮式網箱結構](https://www.fao.org/4/ab766e/AB766E03.htm)、[FAO 牡蠣棚架與垂掛養殖](https://www.fao.org/4/t8598e/t8598e05.htm)。

視覺驗收範圍為上述改動款式的單體與邊界排列；並非全型錄逐款人工驗收。自動檢查涵蓋全部 56 款邊界的 17,920 組種子／段長包絡、實際 Three.js 幾何，以及浮式網箱經正式動態更新後的水線位置。結構測試另外驗證四面體夾角、臂根接合、蚵棚支撐及水下網底。

驗證入口：`test/environmentStructures.mjs`、`test/environmentObjects.mjs`、`test/environmentRender.mjs`（需 `THREE_MODULE`）、`test/architecturePreviewSyntax.mjs`、`test/edgeSlope.mjs`、`test/venueBoundaryAppropriateness.mjs`、`tools/audit_world_edge.mjs`、`tools/audit_edge_fill.mjs`、`tools/audit_gpu_lifecycle.mjs`、`tools/audit_client_syntax.mjs`。

上述為低模美術參數，非工程規範。等比例 fit 後仍收在原固定碰撞包絡，亂數僅使用物件／模組局部種子。此輪視覺抽驗包括廠房、溫室單體與邊界排列、陸域風機、太陽能陣列；未逐一人工驗收所有 56 款邊界。

預覽入口另修復多餘大括號、缺失滑鼠拾取處理及重複種子欄位。回歸：`node test/environmentStructures.mjs`、`node test/architecturePreviewSyntax.mjs`，並搭配既有 environmentObjects、environmentRender、edgeSlope 與邊界稽核。

流程：資產與地形並行準備 → 確定性選址／組裝 → 原型幾何編譯 → 配色分批 → 場景部署。

啟動不呼叫 AI 生成服務。正式零件資料在本機組裝成真正的頂點、法線與色彩緩衝，再建立 Mesh／InstancedMesh；環境物件直接使用程序生成，不再預載舊零件庫。雲端、區網與單機共用此流程。

| 階段 | 入口 | 契約 |
| --- | --- | --- |
| 準備 | `main.js startPrebuild` | 模型與地形並行；戰鬥模型與路網準備完成才建場景 |
| 組裝 | `backgroundObjects.js` | 座標種子決定主結構、葉零件與配色，不消耗共享亂數 |
| 編譯 | `runtimePartModel.js` | 不可變成品保留最多 32 份最近使用原型；每個實體取得獨立幾何，編輯中的資料不快取 |
| 批次 | `sceneObjects.js deploySceneObjects` | 同外觀共用一次幾何取得與一顆 InstancedMesh；矩陣由呼叫端提供並檢查有限值與正尺度 |
| 部署 | `sceneObjects.js deploySceneBatches` | 每款完成後透過既有啟動讓步器更新進度；配色容器攤平，建築淨空能找到所有實例 |
| 風格 | `toon.js sceneObjectMat` | 三階賽璐璐、平塗、冷色暗面、低邊緣光；描邊使用既有單次後製 |

建築已接集中批次部署；場景載具與列車使用快取的成品幾何，保留各自可移動的物件樹。植被、原生地標、NPC 與戰鬥單位仍由其專用建構器處理。

加入新的靜態物件消費端時，先產出已定案的 placements，再向 `deploySceneObjects` 提供 `variantOf`、`geometryOf`、`material`、`matrixOf`、`name` 與 `metadata`。權威尺度與碰撞資料由原消費端管理，禁止由渲染結果反推。使用世界曲面時維持 CPU 視錐剔除關閉。

`pre.prepareMs` 記錄啟動並行準備耗時；`biomes.userData.sceneDeployment` 記錄建築部署數量、原型數與耗時。這些是 CPU 建構量測，不代表整場首次繪製時間或 GPU draw calls。

驗證使用遊戲相同的 Three.js 0.160 模組，無需加入 npm 依賴：

```powershell
$env:THREE_MODULE = 'C:\path\to\three.module.mjs'
node test/sceneObjects.mjs
node tools/audit_client_syntax.mjs
node tools/audit_runtime_scene_models.mjs
node tools/audit_background_objects.mjs
node tools/audit_gpu_lifecycle.mjs
```

實體測試涵蓋 2,000 個 placement 合為 4 個批次、全部 29 款建物、多配色淨空可見性、無效矩陣拒絕、快取副本隔離與編輯刷新。輸出的冷／暖編譯時間只供本機診斷，不設定跨硬體效能斷言。

## 共用程序環境物件（2026-09-10）

`environmentParts.js` 是 17 類獨立物件的共同生成入口：住家、摩天樓、倒塌高樓、工廠、電廠、焚化廠、礦場、油田、溫室、牧場、巨石、神木、倒木、汽車、擱淺船、浮冰與冰山。`backgroundObjects.js` 的 `environment/` 目標與 `edgewall.js` 的獨立邊界類型雙向共用。樹、岩石、車與船體沿用各自既有程序生成器。

邊界用途尺寸由型錄與段長固定，種子只改造型、配置和配色。外觀可見空隙仍由連續權威碰撞環封閉，禁止穿越；碰撞高度不隨隨機模型降低。消波塊、風機、堤防、城牆及其他陣列／長構造由模組種子重新生成，僅列入邊界型錄。

場內共用物件使用座標獨立種子選址，避開兵線、出生區、道路、圖資建築、水域與陡坡；碰撞由生成零件推導。新增物件不消耗植被共享亂數。一般 OSM 建物由既有多邊形程序建築生成器產生。

驗證：`node test/environmentObjects.mjs`；實際 Three.js 幾何檢查為 `THREE_MODULE=<本機 three.module.js 路徑> node test/environmentRender.mjs`。

### 邊界陡坡接縫

`edgeSlope.js` 以世界座標對齊的取樣站與固定斷面生成連續表面，城牆、路障、河堤、海堤、懸崖、山崩地、土石流的相鄰段共用端面座標。視覺段長取實際間距，避免重疊高低階差；碰撞盒保留原有重疊環，並包含整個貼坡表面的高低範圍，空隙仍不可穿越。

陡坡必須同時通過坡度上限與 `terrainFit` 能力檢查；剛性建築、車輛、風機、消波塊等不具連續貼坡能力者不加入陡坡候選。坡度量測涵蓋最深障礙物的完整外側底部。

驗證：`node test/edgeSlope.mjs`，以及模型對照頁的「陡坡：三段連續接縫」。

## 環境模型整合與冰體（2026-09-13）

正式一般建物原已固定使用 polygonBuilding；移除永不命中的 fitApprovedBuilding 呼叫。保留原建場後段亂數抽取次序，避免植被與其他布局位移。舊 v5/v6 模型、來源帳及組裝器仍供審核工具使用，不刪歷史資產。

舊規則盤點與處理：

| 舊規則 | 處理 |
| --- | --- |
| 場景／邊界各自組裝樹、岩、建物 | 共用 environmentParts；緩衝區與遠景森林、城市、島影也改用同一生成器。後兩個 API 目前供預覽／工具使用，正式遊戲由權威邊界環承接 |
| 低模山峰與季節雪冠 | 保留有合理斜率與接合測試的決定性配方 |
| 住家屋頂固定中心高度與長度 | 由半跨與坡角計算斜長及屋脊，消除屋脊間隙 |
| 任意 2–4 或 8–16 層，忽略高度 | 層數與窗跨由實際量體尺寸和分類參數推導 |
| 冷卻塔疊在廠房屋頂 | 移至廠房旁並接地 |
| 冰脊套用連續岩丘斷面 | 移除岩丘配方，seaice 重用 icefloe 組成碎裂冰帶 |
| 固定緩衝區錐形樹／孤立屋頂／人造海面方盒 | 移除重複配方，轉接森林、建物及岩石生成器；海面由地形處理 |

分類與尺寸由 environmentCatalog.js 集中管理；environmentParts.js 僅組裝描述子。共有 17 種單體，分為住宅、高樓、工業、採掘、農牧、岩石、巨木、倒木、車輛、船舶、海冰、冰川冰 12 類。56 種邊界仍區分單體與長構造，坡面工程沿用 edgeSlope 的連續斷面，不能把長構造任意拆成場內單體。

| 類別 | 場內公稱尺寸倍率 | 額外參數 |
| --- | --- | --- |
| 住宅 | 0.72–1 | 層高 2.8–3.6 m；窗跨 2.2–3.6 m |
| 高樓 | 0.75–1 | 層高 3.2–4.2 m；窗跨 2.4–4 m |
| 工業 | 0.8–1 | 層高 4.5–6 m；窗跨 3.5–5 m |
| 採掘／農牧／船舶 | 0.8–1 | 重用各專用生成器 |
| 岩石／巨木／倒木／車輛 | 0.6–1／0.75–1／0.65–1／0.9–1 | 等比例縮放，仍受世界高度上限限制；岩石單體另帶種子隨機朝向（連續無縫的邊界連排除外） |
| 浮冰 | 0.5–1 | 公稱 24×2×18 m；8–14 邊；徑向倍率 0.78–1；單體帶種子隨機朝向（連續無縫的邊界連排除外） |
| 冰山 | 0.65–1 | 公稱 38×36×28 m；7–12 邊；徑向倍率 0.65–1；40% 平頂，其他為收窄冰冠；單體帶種子隨機朝向（連續無縫的邊界連排除外） |

尺寸順序是寬×總高×深。範圍是遊戲美術設計值，不是自然物統計或工程施工規格；邊界公稱包絡維持固定，外觀以等比例縮放收在包絡內。海冰和冰川冰的區分參考 [NSIDC 海冰科學](https://nsidc.org/learn/parts-cryosphere/sea-ice/science-sea-ice) 與 [NOAA 冰山說明](https://oceanservice.noaa.gov/facts/iceberg.html)。小型／壓縮後冰體不宣稱符合 NOAA 的冰山尺寸分類。

iceParts.js 產生封閉多面體、冰冠、斷裂邊緣與水下龍骨。浮冰／冰山的水線分別位於總高的 86%／84%，是簡化造型參數，並非按體積解浮力。水線寫入描述子，場景與邊界共用；邊界碰撞環仍保持原固定高度。場內冰體登記同源有向包絡，保持靜態，不做僅客戶端漂移。

場內完整矩形足跡以最多 2 m 間距檢查水深、內部淺灘、乾地帶與有效取樣。龍骨離底不足 0.3 m 就省略；道路、兵線、出生點及既有物件避讓保持有效。水面缺失時不生成。冰體幾何封閉但碰撞仍採既有保守盒，不是逐三角形冰面碰撞。

自然生成沿用 forestEnvironment 的溫度推估：浮冰需 ≤2°C、冰山需 ≤8°C；缺乏可推估氣候時省略。此條件表示適用的遊戲氣候，不證明現地存在冰川。cfg.env.ice 可明確開關冰體，供自訂冰雪地圖使用。場景與邊界都套用此閘，預覽可直接檢查全部款式。

驗證：environmentObjects（17,920 組包絡、封閉網格／繞序／水線／淺灘）、environmentRender（正式 Three.js 編譯與頂點包絡）、edgeSlope、audit_world_edge、audit_edge_fill、audit_siteplan、audit_world_height、audit_client_syntax、audit_gpu_lifecycle。
