# 角色 / 機體檔案 — 標準格式規格

> 2026-08-04 使用者定案:「角色與機體的完整數據與文字說明的格式**完全對齊**,特別是機體原型的介紹,
> 也包括**不顯示與遊戲**、用於**文本生成 / 2D 生圖 / 3D 建模**使用的部分,都統一標準格式。」
>
> **格式**的唯一真相 = [`public/js/codex.js`](../public/js/codex.js);本文只是它的人類可讀版。
> 兩者對不上時以程式為準,並回頭修本文。稽核 `node tools/audit_codex.mjs`(60 項)。

---

## 一、為什麼要做這件事

改制前,「角色」與「機體」在資料上根本不是同一個東西:

| | 改制前 | 症狀 |
|---|---|---|
| 角色 | `lore.js` 12 個欄位,32 名全數齊備 | 尚可 |
| 機體 | 一條自由字串 `lore.proto`,由 `main.js` 用正規式切四個標籤 | 32 台長出 **4 種標籤**(現實/機體/體態/仿生);**8 台只有一層**;變形者的兩個型態被擠在同一句「A ↔ B」裡 |
| 生成用資料 | **完全沒有** | 文本生成/生圖/建模全靠人去翻 `data.js` 註解 + `models.js` 註解 + 這條字串 |

自由字串的要害不是難看,是**沒有任何東西會報錯**:少寫一層、標籤打錯、兩個型態併成一句,
遊戲照樣跑、畫面照樣顯示,只是那台機體的介紹比別人少一塊,而且沒人會發現。

改制後,格式是**結構性**的:欄位表只有一份、原型層由 `visual` **推導**,漏一層就是稽核紅字。

## 二、四段結構(兩種檔案共用)

`codex.js SECTIONS` 定義,兩種檔案的段落**相同**:

| 段 | 顯示於 | 角色 | 機體 |
|---|---|---|---|
| **識別** ident | 卡片 | 姓名 / 呼號 / 陣營 / 機種 / 駕駛機體 | 型號 / 機體名 / 陣營 / 機種 / 駕駛員 |
| **簡介** brief | 卡片 | 國籍 / 年齡 / 性別 / 職務 / 外貌 / 台詞 | **原型層**(見第三節) |
| **詳閱** deep | 立繪跳出視窗 | 生平 / 興趣 / 專長 / 與機體的機緣 | 與駕駛員的機緣 |
| **生成** gen | **不顯示** | 立繪參數 `art` + 六欄 | 外觀參數 `visual` + 六欄 |

識別段的值**一律到原處取**(`data.js CHARACTERS`),`lore.js`/`mecha.js` 不存第二份 ——
改了 `data.js` 的機體名,圖鑑與三份生成文字同時跟著動。

## 三、原型層(機體原型的介紹)

`codex.js PROTO_LAYERS`。**哪一台該有哪幾層是推導的**,`from` = `visual` 的哪一個欄位決定它存不存在:

| 層 | 顯示標籤 | 存在條件 | 台數 |
|---|---|---|---|
| `real` | 設計原型 | 恆有(工程出處) | 32 |
| `frame` | 機體原型 | `visual.proto`(人形機甲的裝甲哲學) | 4 |
| `bionic` | 仿生原型 | `visual.creature`(獸型機體取自哪種生物) | 12 |
| `air` | 飛行型原型 | `visual.flight`(變形者的飛行型態) | 8 |
| `ground` | 地面型原型 | `visual.ground`(變形者的地面型態) | 8 |

合計 **64 層**。變形者因此**恆有兩層形態原型** —— 舊制把「始祖鳥 ↔ 迅猛龍」寫成一句話,那是一層不是兩層。

每層恰兩欄,**MUST NOT 揉成一句**(揉了就退回自由字串):

```js
bionic: {
  src:  '半人馬(代號「凱隆」)',                    // 原型出處的名稱 → 可直接當生圖關鍵詞
  note: '神話裡唯一不打獵的半人馬,教人療傷…',      // 「為什麼是它」的設計理由
}
```

## 四、生成段(不顯示於遊戲)

`codex.js GEN_FIELDS`。**角色與機體同鍵同義** —— 這就是「格式完全對齊」那句話的落點:
同一支外部工具讀角色與讀機體是同一段程式。

| 欄 | 型別 | 機體 | 角色 |
|---|---|---|---|
| `sil` | 文字 | 剪影 —— 輪廓一眼認得出什麼 | 體態與站姿的剪影 |
| `mass` | 文字 | 各部佔比與重心 | 身高體格與比例 |
| `mat` | 文字 | 表面處理、磨損、透光 | 膚髮與衣料質感 |
| `parts` | 清單 | 3D 可分離量體(由主到次,≥ 4 件) | 服裝配件分件 |
| `tag` | 清單 | 生圖關鍵詞(**名詞短語**,≤ 14 字、無標點) | 同左 |
| `note` | 文字 | 這一台最容易被建錯的那一件事 | 這一位最容易被畫錯的那一件事 |

**MUST NOT 只在其中一邊加欄位**(加了就不是同一個格式);要加就兩邊一起加,並補上稽核。

> `mass` **MUST NOT 寫公尺數**:全高由 `heroTargetH(kind, ch)` 推導(隨角色護甲在機種區間內插),
> 手寫一個數字的症狀是「改了 `mods.armor`,建模單沒跟著動」。角色的尺度基準恆為 `SOLDIER_H`(1.8m)。

## 五、三份對外的生成文字(全部由 `codex.js` 組裝)

| 函式 | 用途 | 內容 |
|---|---|---|
| `textSeed(kind, id)` | **文本生成**(LLM 設定輸入) | 四段全文攤平 + 推導的尺度基準 |
| `imagePrompt(kind, id)` | **2D 生圖** | 名詞關鍵詞串(去重)+ 剪影 + 材質各一行 |
| `modelSheet(kind, id)` | **3D 建模** | 全高 + 量體比例 + 材質 + 編號分件 + 建模注意 |

三份都是**推導**的:欄位一改三份自己跟著改。
**MUST NOT 在 `lore.js`/`mecha.js` 手寫任何一份** —— 手寫的那份不會跟著欄位變,而且沒有任何錯誤訊息
(只是生出來的圖與設定慢慢對不上)。

用法(離線,不需瀏覽器):

```bash
node --input-type=module -e "
  const C = await import('./public/js/codex.js');
  console.log(C.textSeed('mecha', 't06'));     // 文本生成
  console.log(C.imagePrompt('char', 's05'));   // 2D 生圖
  console.log(C.modelSheet('mecha', 's01'));   // 3D 建模
"
```

## 六、內容住哪裡

| 內容 | 檔案 | 備註 |
|---|---|---|
| **格式**(段/欄/必填/組裝) | `public/js/codex.js` | 唯一真相 |
| 角色敘事 + 角色生成段 | `public/js/lore.js` | 客戶端專用 |
| 機體原型 + 機體生成段 | `public/js/mecha.js` | **零 import**(離線管線直接吃真品) |
| 平衡數值 / 外觀參數 / 機體名 | `public/js/data.js` | 伺服器也 import |
| 運動性格 / 施法性格 | `public/js/models.js` | `MOVE_SIG` / `CAST_SIG` |
| 劇情與角色設定集 | `docs/characters.md` | 含不得出現在遊戲內的三分律設計原型 |

機體換手時,`mecha.js` 那一整格連同 `visual` 機體欄、`mods`、`MOVE_SIG`/`CAST_SIG` **一起搬**
(CLAUDE.md §2.1 角色機種);1:1(一台機體恰一名駕駛)由稽核釘住。

## 七、稽核

```bash
node tools/audit_codex.mjs                 # 60 項(不需伺服器/瀏覽器/網路)
node tools/audit_codex.mjs --break-layer   # 反向:抽掉一台的原型層 ⇒ ②③ MUST 紅字
node tools/audit_codex.mjs --break-align   # 反向:角色生成段多一欄 ⇒ ① MUST 紅字
```

五段不變式:① 格式對齊是結構性的 ② 原型層由 `visual` 推導 ③ 32×2 份全數填滿
④ 單一縫(值到原處取、生成文字只由 codex.js 組裝、`main.js` 不再切標籤字串)
⑤ 生成輸出真的是推導的(改一個欄位,輸出跟著變)。

## 八、機體美術覆核台(臨時工具,dev-only)

```bash
npm run codex                            # 起覆核台 → http://localhost:8621/
node tools/codex_review.mjs --report     # 不開瀏覽器,直接印配對表
node tools/codex_review.mjs --port 9000
```

把 `public/assets/cyberpunk_art/mechs/` 已生成的機體圖,配到角色頭像與 3D 展示台旁邊,一格一格覆核:

- **配對是推導的** —— 檔名 `<角色 id>[_<型態>]_<姿態>.png`;「這台該有哪幾張」由 `visual.flight`/`visual.ground`
  推導(與原型層同一條規則)⇒ 變形者 6 張、其餘 3 張,合計應有 120 張。
- **缺圖與孤兒不藏** —— 缺的畫成灰框、對不到任何一格的列在頁尾。首跑實測:**61/120 張到位、
  12 名角色一張都沒有、3 張孤兒**(`s03_*.png` 是她還是無人機時出的圖,2026-08-03 換成變形者後檔名少了型態段)。
  孤兒可在頁面上**指派**到某一格,不必改檔名。
- **點圖 → 覆核**:① 確認勾選(通過 / 局部重繪 / 重下 prompt)② 在圖上**拖曳框出要重畫的地方**
  (存成正規化 bbox + 逐框說明,可直接餵 inpaint)③ 重新下 prompt(預設 = `imagePrompt()` 推導值,
  改過的才存;有「還原成推導值」)。
- **旁邊就是遊戲那一台 3D 展示台**(`charPreview.js`,點武器/招式列會播演出)、武器招式數值走
  `heroWeapon`/`heroAbility`、**遊戲未公開的生成段**(機體六欄 + 角色六欄 + `modelSheet` + `textSeed`)一併攤開。

三條邊界:**住 `tools/` 不住 `public/`**(`build_solo` 是把 `public/**` 整包複製,放進去就會出貨)、
**唯讀遊戲資料**(覆核結果只寫 `tools/codex_review/state.json`,那是覆核產物不是第二份 `imagePrompt`)、
**three 拿不到就降級**(3D 那一格顯示原因,其餘照常 —— 原則 6)。

> `state.json` **要 commit**:遠端容器會被回收,沒進版控的覆核紀錄就沒了。
