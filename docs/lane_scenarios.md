# 1v1 兵線立體場景測試地圖

手動測試「兵線上的立體交通結構」時,不必自己在世界地圖上找位置 —— 下面八種場景各自指定一張
**預設場地**,開 1v1(每邊 1 人 ⇒ 1 條兵線)直接選那張場地即可。

場地清單的滑鼠提示(桌機把游標移到場地按鈕上)會顯示該場地 1v1 兵線實測走得到的場景;
鈕面刻意不寫(見 `/CLAUDE.md` A20:鈕面 MUST NOT 加括號補述)。

## 各場景的測試地圖(1v1 = 每邊 1 人)

**隧道與地下道是兩種東西,分開處理**:

- **隧道**:道路平坦,鑽進突起的地形 —— 深度來自**山**。
- **地下道**:地形平坦,路面一端往下、另一端再上來 —— 深度來自**挖**。
  2026-07-28 起引擎會生成(見下方「② 地下道怎麼生成的」)。

| # | 場景 | 用這張場地 | 實測到什麼 |
|---|---|---|---|
| ① | 隧道(山體) | **台北・內湖金龍隧道** | 兵線走進金龍隧道覆蓋段 **257 m**(路面深度中位數 15 m) |
| ② | 地下道(平地下穿) | **台北・市民大道** | 兵線走在一段 **60 m** 的圖資地下道上;引擎接上下沉剖面後,該段兩端各接一條引道、中段成洞 |
| ③ | 地面高架橋(純陸域) | ❌ **尚無** | 見下方「未解場景」 |
| ④ | 明隧道 | **台北・內湖金龍隧道** | 金龍隧道單側土牆藏不住結構,**36 m** 改明隧道 |
| ⑤ | 平交道 | **德國・黑森林** | 平交道節點就落在兵線上(距離 1 m) |
| ⑥ | 穿越高架橋底部 | **開羅・吉薩金字塔群** | 兵線從一條 213 m 的**陸域**公路橋下方鑽過;備選 台北 101(人行空橋)、倫敦(Westminster Bridge) |
| ⑦ | 穿越地下道上方 | ❌ **尚無** | 見下方「未解場景」(2026-07-29 資格閘後澀谷失效) |
| ⑧ | 一側高於一座砲塔(一般道路) | **里約・基督山海岸** | 單側高地連續 **264 m**、峰值 **+73 m**(門檻 26 m),全程一般道路 |

**⑧ 為什麼扣掉結構段、為什麼不是金龍**:在地下道裡側面地形之所以「比兵線高」,只是因為
**路面沉得深** —— 那個高度差就是地下道的深度,不是可以佔領的戰術高地(站在橋面上比更沒意義)。
金龍的高地有一大段正是隧道段本身,扣掉後只剩 159 m/+42 m;里約沒有任何結構,264 m 全是一般道路對峙。

## 未解場景與原因

### ③ 純陸域高架橋:目前沒有場地
倫敦 Westminster Bridge 是**跨水橋**(與圖資水道相交),依使用者要求不算 ②。
掃描找到的陸域高架橋都不在兵線上:曼哈頓 Park Avenue 高架 254 m、吉薩 213 m(兵線從**底下**過)、
威尼斯 Cavalcavia 422 m。已為此在烘焙器加了 `PREFER_BRIDGE`(選線先比「踩在橋上的長度」),
以 Park Avenue 高架試了三輪(夾方位角 / 放開方位角 / 偏好),兵線最近只到橋旁 **4 m**,
沒真的踩上橋面 —— 曼哈頓格柵等長替代路線太多,且高架與地面 Park Avenue 在圖資上是分離的 way。
候選錨點保留在 `tools/bake_venue_lanes.mjs`(`parkave`),待換場地或加強偏好後再定案。

### ⑦ 穿越地下道上方:2026-07-29 起暫無場地
舊指定場地是東京・澀谷(兵線橫越明治通り正下方的「人行地下道」覆蓋段),但那條 way 其實是
澀谷站的**室內人行地下街**(OSM `highway=footway` + `indoor=yes` + `tunnel=yes`),被當成
山體隧道建洞後,自家敞開段的 hw+7 斜壁開挖把覆蓋段側壁挖成走得出去的破口(澀谷側壁破口案)。
`strucTunnel` 結構資格閘上線後,人行/室內 tunnel way 一律攤平不成洞 ⇒ 澀谷的 ⑦ 隨之失效
(實測 scen 只剩 `underBridge`)。澀谷 bbox 內僅剩的 ⑦ 候選(間坂×間坂)離兵線 387m 不成立;
要補 ⑦ 得物色「**車行**地下道 + 兵線從洞頂跨過」的新場地,待下一次全量掃描(需外網)定案。

### ② 地下道(平地下穿):2026-07-28 之前的缺口
舊制的隧道路面 = **兩端洞口地表高的直線內插**,平地上路面 = 地表,永遠達不到覆蓋門檻
(地表 ≥ 路面 + `TUN.CLEAR` 8 m + `ROOF_T` 1 m),`buildRoads` 一律當一般道路(不開挖、不立門洞)。
`--probe` 當時實測八個候選點全部 **0 條成洞**:

| 探測點 | 車行隧道 | 成洞 |
|---|---|---|
| 紐約中央公園 79 街橫貫道 | 3 | 0 |
| 紐約中央公園 65 街橫貫道 | 2 | 0 |
| 京都・蹴上 | 2 | 0 |
| 巴黎・河岸下穿 | 3 | 0 |
| 台北・市民大道 | 8 | 0 |
| 東京・六本木 | 2 | 0 |
| 巴塞隆納 | 2 | 0 |
| 台北・自強隧道口 | 0 | 0 |

⇒ 「換張地圖」解不了,要改引擎。

### ② 地下道怎麼生成的(2026-07-28)
判定順序與山體隧道**完全共用**,只換路面剖面(`biomes.js underpassPlan` / `tunFloorAt`):

1. 直線剖面藏得住天花板 ⇒ 山體隧道(舊路徑,逐位元不變)。
2. 藏不住(= 平地)⇒ 試地下道:兩端沿端點切線各接一條**引道**(夾在圖界內),路面以 smoothstep
   自地表沉到 −`sink`(平地上 = 8 + 1 + `MARGIN` 1.2 = **10.2 m**),中段平底。
3. 中段的**原地表完全不開挖**,自然高過 路面 + 淨空 + 頂板 ⇒ `tunnelCoverIntervals` 照原判定
   判成覆蓋段 = 洞。頂上就是原本那片地/那條橫向道路。
4. 引道落在敞開補集 ⇒ `carveTunnels` 照原規則開挖成路塹;洞口那面橫塞斷面的土牆由
   `punchPortalHoles` 打穿 = 出入口的「可穿透透明牆」(純視覺,`heights[]` 不動 ⇒ 碰撞/LOS 不變)。
5. **邊緣修飾**:引道兩側的擋土牆頂到「一般路面高 + 護欄 `KERB`」,牆外再鋪一條 `COPE` 寬、
   與一般路面同高的緣石帶蓋住開挖斜壁 ⇒ 從外面看是「街廓 → 緣石 → 護欄 → 下沉車道」,
   接縫處路面高與外部一般道路逐點相同(smoothstep 兩端切線為 0 ⇒ 連坡度都連續)。

引道長由下沉量與縱坡推導(`1.5 × sink / GRADE`,目標 12%、上限 22%),擠不出來就放棄 ——
連同「人行道 / 要挖到 `SINK_MAX` 以上 / 走廊碰水」四條放棄條件,一律退回一般道路(§4 寧缺勿錯)。
驗證:`node tools/audit_underpass.mjs`(81 項離線直測 + 反向驗證)。

**② 的指定測試場地:台北・市民大道**(`civicblvd`)—— 從探測候選裡挑最密的一區
(L1 bbox 內圖資有 8 條車行 tunnel way),烘焙器以 `PREFER_TUNNEL` 選線,實測 1v1 兵線
走在一段 **60 m** 的圖資地下道上。現有 22 個預設場地的兵線都沒有這種路段(已複驗),故新增。
`venues.js` 的 `scen` 標記**要等下一次全量掃描(需外網)實測後才補**——標記 MUST 由實測產生。

> 名詞:「地表高 − 路面高」在高度場上同時是「路面上方有多少土」與「路面沉在地表之下多深」,
> 語意上取後者 —— **地下道的關鍵尺寸是深度**。引擎的覆蓋門檻(9 m)因此等於「最小深度」;
> 舊制在平地上路面沉不下去(深度 0)所以永遠不成洞,現制直接把路面挖到 10.2 m 深。

## 八種場景與判定

| # | 場景 | 代號 | 判定(遊戲內對應) |
|---|---|---|---|
| ① | 隧道(山體) | `tunnel` | 兵線走進 OSM `tunnel` way,且該段**執行期真的成洞**(地表高過路面 + `TUN.CLEAR` + `ROOF_T` ⇒ `tunnelCoverIntervals` 有覆蓋區間)|
| ② | 地下道(平地下穿) | `underpass` | 兵線走在 OSM `tunnel` way 上、地形平坦(直線剖面覆蓋為空),且 `underpassPlan` **規劃成功**(下沉剖面 + 兩端引道)⇒ 中段成洞。規劃放棄的段落仍是一般道路,報告列成「落空地下道」 |
| ③ | 地面高架橋 | `bridge` | 兵線**走在**橋面上,且該橋**跨的是陸域**(與圖資水道相交、或橋下地表沉在水沼面下 = 跨水橋,不算);另 MUST 是車行道且與兵線共用 OSM 節點 |
| ④ | 明隧道 | `gallery` | 覆蓋段的側向土牆藏不住結構(`tunnelWallProfile` 判 `open`)⇒ 該側改蓋外露頂板 + 落地擋土 facade + 扶壁 |
| ⑤ | 平交道 | `crossing` | 兵線上有 OSM `railway=level_crossing` 節點(地面鐵軌與道路平面交會,遊戲內立警示柱 + 抬起的遮斷器) |
| ⑥ | 穿越高架橋底部 | `underBridge` | 兵線與某座橋的走廊**幾何交叉但不共節點** ⇒ 從橋下鑽過(橋面底緣是天花碰撞,跳不穿) |
| ⑦ | 穿越地下道上方 | `overTunnel` | 兵線與某條**覆蓋段**隧道交叉但不共節點 ⇒ 從洞頂的山體地表走過 |
| ⑧ | 一側高於一座砲塔的地形 | `highGround` | 兵線某一側的地形高出兵線 ≥ 一座砲塔高(`altTier()` = `TARGET_H.tower`),連續涵蓋 ≥60 遊戲公尺,且**該段是一般道路** —— 橋面/隧道/引道一律扣掉:洞裡量到的高差是地下道的**深度**,不是戰術高地 |

⑧ 的側向掃描距離預設 300 遊戲公尺(≈ 英雄重武器射程上限):站在那片高地上真的打得到兵線,
高度差加成才有意義。要看更貼身的高地,`--side=150` 重跑即可。

## 怎麼重跑判定

```bash
node tools/audit_lane_scenarios.mjs            # 全部場地
node tools/audit_lane_scenarios.mjs --only=jinlong,london
```

- 需要外網(Overpass 路網 + AWS terrarium 高程);抓過的結果快取在 `tools/.scen_cache/`,
  之後純離線可重跑。沙箱沒有這兩個出口時,改跑 GitHub Actions 的「兵線場景掃描」workflow。
- 判定與執行期同源:兵線走 `venueConfig(v, 1)`、bbox 走 `battleBBox`、路網查詢字串與
  `biomes.js` 同一份、高程走 `terrain.js` 的 terrarium 主來源並重跑同一條高度管線;
  隧道覆蓋、地下道規劃、明隧道**直接執行 `biomes.js` 的函式原文**。
- 稽核同時複驗 `venues.js` 的 `VENUES[].scen` 標記:多標/漏標一律紅字。
  **標記 MUST 由實測產生**,不得手寫臆測。

## 為什麼判定要「執行期真的成洞/成橋」

OSM 的 `tunnel`/`bridge` tag 只說現實世界有這個結構,遊戲裡建不建得出來還要看地形與規劃結果:
平坦市區的 tunnel way 沒有山體可以藏天花板,要靠 `underpassPlan` 挖出來 —— 而它會因為
「人行道 / 引道空間不足 / 要挖到 `SINK_MAX` 以上 / 走廊碰水」放棄,放棄的那些仍是一般道路。
稽核因此一律把覆蓋區間(含地下道規劃)算出來再判,避免「圖資有、遊戲裡沒有」的假陽性。
