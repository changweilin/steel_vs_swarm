# Gemini img→3D Pipeline

Convert reference photos into reviewed **part-library inputs**, never finished whole props. Preserve the server/game
contracts, licensing boundary, provenance, deterministic layout, and human approval gate.

## Mandatory context

Before acting, read these files completely or the named sections where specified:

1. `../../../AGENTS.md`.
2. `../../../docs/ai3d_handoff_2026-08-18.md`.
3. `../../../docs/anime_style_plan.md`.
4. `../../../docs/ai3d_runbook.md` §0, §1, §4, §5aj, and the 2026-08-18 section.

Read [references/runner-contracts.md](references/runner-contracts.md) when installing, locating, wrapping, or invoking a
model runner. Read [references/execution-gates.md](references/execution-gates.md) before processing a corpus, replacing
an asset, or declaring completion.

## Non-negotiable boundaries

- Keep the output a vocabulary of reusable parts. Do not bake complete trees, buildings, vehicles, ships, or landmarks.
- Route regular man-made objects to Route A pure-data parts. Do not send them to GPU merely because a runner exists.
- Keep `shipping:false` corpora out of active provenance, GLBs, game rosters, and replacement decisions.
- Run Hunyuan shape-only. Never run its paint/PBR stage.
- Parallelize CPU preprocessing across families only. Keep GPU model execution single-lane on a 12GB card.
- Do not invent upstream entrypoints or flags. Read the checkout's README and adapt it behind the local runner contract.
- Do not add npm dependencies, a build system, TypeScript, or a framework.
- Do not alter authoritative collision, LOS, reach, balance, or deterministic shared-random consumption for visual parts.
- Do not remove an old part until its replacement passes human review. Archive its provenance with `replaced_by`.
- Do not commit, push, purge photos, or accept review results without explicit authorization. Pipeline scripts themselves
  must never commit.
- Preserve unrelated worktree changes. Never reset or clean them.

## Routing decision

Use `tools/ai3d/pipeline_policy.mjs` as the executable source of truth:

| Family/class | Route | Required output |
|---|---|---|
| `building` mass | T2-spz | GLB part, binary input, solidified before normalize |
| `rock` | Hunyuan3D-2GP shape-only | GLB part |
| sculptural `tree` only | SF3D | GLB part |
| small vegetation/canopy repetition | Existing procedural system | No generated mesh |
| `landmark`, `vehicle`, `ship` | Route A / `llm_parts` | Pure-data primitive part rows |
| unknown family | Hold | Report the missing consumer contract; do not guess |

If documentation and `pipeline_policy.mjs` disagree, stop and report the conflict. Do not silently choose one.

## Execution workflow

### 1. Establish state

Run read-only checks first:

```powershell
git status --short
git log -1 --oneline
node tools/ai3d/replacement_plan.mjs --home <formal-home> --home <restricted-photos>
```

Treat existing changes as user-owned. The expected code baseline is documented in the handoff file, not assumed.

### 2. Resolve runners

Locate existing Python 3.11 environments, model checkouts, weights, Blender, and adapters before installing anything.
Verify each runner with one photo and `--no-intake`. If any runner is missing, provide its exact missing files and stop
that route while continuing safe CPU/contact-sheet work.

Never label a fallback output as a replacement generated by the preferred route.

### 3. Process restricted corpus first

Accept either the data-home root or its `photos` child; `normalizeCorpusHome()` must recover the parent declaration.
Run indexing and preprocessing, then confirm the log says `非出貨語料家` and all intake stages are skipped. Route A
families may be inspected for authoring but may not be shipped.

### 4. Smoke-test formal routes

Run one image each for building, rock, and sculptural tree with `--no-intake`. Inspect `.feed.json`, GLB layout, method,
source photo, target, family, part, contact sheet, and GPU/RAM behavior. Only after all three pass may a continuous run
start.

### 5. Generate in small batches

Use `--category-jobs 3`, `--gen-limit 12`, `--t2-limit 4`, and `--intake-limit 4` unless measurements justify lower
values. Keep family-internal preprocessing ordered and GPU generation sequential. Do not hide caps or skipped items.

### 6. Review and replace

Print `replacement_plan.mjs` before each batch. The current baseline contains 61 legacy keys: 11 automatic roster-slot
replacements and 50 fixed-slot/Route A items requiring explicit recipes.

For automatic slots:

1. Require `.feed.json.replaces` and a same-slot check.
2. Run auto intake and its full gate.
3. Open the parts review board and inspect source image, method, silhouette, seams, scale, and fallback envelope.
4. Apply `replace` only after human approval.
5. Verify the new key remains active and the old key moves to archive with `replaced_by`.

For fixed slots or Route A, inspect the consumer and add an explicit recipe/builder contract. Never create a generic
replacement shortcut to make the queue count reach zero.

### 7. Validate each batch

Run the pristine audit and adjacent asset audits listed in [references/execution-gates.md](references/execution-gates.md).
If code judgment changed, also run the corresponding `--break-*` reverse test and require non-zero exit. Asset-only
batches still require the pristine audit, part intake checks, review-board gap report, balance, and final e2e.

### 8. Report truthfully

Report runner checkout/commit, Python/CUDA/Blender versions, per-route counts, legacy keys replaced/blocked, archive
links, restricted-corpus status, validation results, and unverified visual or dependency checks. Missing runners mean
the mesh generation stage is blocked; do not describe pipeline scaffolding as completed conversion.

## Stop conditions

Stop the affected route and preserve artifacts when any of these occur:

- corpus licensing state is missing or contradictory;
- a requested family lacks a consumer seam or fallback envelope;
- preferred runner cannot be identified from upstream documentation;
- output method/provenance disagrees with the selected route;
- review-board gaps are nonzero;
- a pristine audit fails or a required reverse audit stays green;
- replacement would remove the final roster entry or touch a different slot;
- GPU OOM, T2 system-RAM exhaustion, corrupt GLB, or missing `.feed.json` occurs.

Continue independent safe work only when doing so cannot mutate shipping assets or obscure the blocker.
