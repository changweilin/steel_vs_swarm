## 2. 模組級地雷(依領域;全域 A 表/縫索引已覆蓋者不重複)

### A. 權威結算與戰鬥(sim / data / game)

- 單機序列化:`_serializeEnt` MUST NOT 洩漏權威可變物件的參考(巢狀欄位一律展開複製,如 `o.up = {...e.upg}`)—— 單機傳輸層不經 JSON 深拷貝,客戶端樂觀更新會就地改到伺服器狀態(雙重遞增)。
- 塗層阻擋(A6b)入口三層:`_terrainSegT`(地形,唯一走 `rayTerrain`)→ `_obstHitT`(障礙盒/圓柱 ∪ 橋面/天花/**路面**薄板)→ `_layerHitT`(兩者取近)。表現層彈體 `_updateVisShells` 與榴彈虛線 `_arcTrace` MUST 吃 `_layerHitT`;`_updateBullets`/`_resolveAim` 自己併 `_terrainHitT` + `_obstHitT`(需要分辨 hit.terrain)。`_slabHitT` 的 `!tn.open` 閘同時管天花與路面。爆點回報(`t:'burst'`)洞內的離地基準 = `btn.floor`(heightAt 是未開挖的山頂),但 `lev` 刻意只報 0/2(橋面報 1 = 橋上砲塔 AoE 免傷)。
- 貫穿:首個目標 MUST 全額(bal 不變式);`ARMING` 最短距離內導引 MUST NOT 接手、`b.oy` 擊發當下取樣;bot 的 line 分支吃加粗但射線長維持 bot 自己的射程判定。
- 榴彈:越障 MUST 走 `LOB_CHARGE` 降裝藥(同初速高角解 = 85°、飛 20 秒);`_lobAim` MUST 保留瞄準點快取(每幀 `_resolveAim` 是 3.7ms 熱點);最小射程唯一縫 `lobMinRange(def)`(爆風半徑推導),過近自損由 `blastFalloff` 導出,MUST NOT 另寫公式。降裝藥階梯與彈道積分收在 `_lobLadder` / `_arcTrace(…, draw)` 兩支:繪製走 draw=true(寫 `_arcGuide` 緩衝)、射程光暈的可命中判定走 draw=false ⇒ **判定端 MUST NOT 自己寫一份簡化積分**(那正是「光暈亮著卻沒命中」的成因)。
- 射程光暈(2026-07-30 使用者回報「榴彈類常常光暈亮著卻沒命中對方」):語意是**打得到**,不是距離夠近。判據唯一縫 = `data.js reachRule()` → `game.js _reachable()`,逐彈道五類分派 —— 拋物線跑火控階梯、直線跑 `_layerHitT` 線段;爆炸戰鬥部看「落點是否落在 `blastCoreR` 核心帶內」(**刻意不要求 LOS**:爆風不吃 LOS,A11 繞射近似 ⇒ 貼著掩體炸開照樣亮),直擊/貫穿看「線段整段淨空」(對齊伺服器 `_losBlocked`)。三個無聲寫壞法:①退回只量距離(回到原病灶);②在光暈那邊多加 `if (def.type…)`(第二份分類表 = 與 `trajClass` 分家);③每幀替全場敵人重算彈道積分(把 `_lobAim` 熱路徑乘上敵人數)—— 節流走 `RANGE_GLOW`(每幀固定枚數 + TTL 快取 + 換武器/重砲窗整批作廢),**尚未評估過的目標不亮**(寧缺勿錯)。警示色(琥珀)= 打得到但命中率低/會自損:榴彈最小安全射程內、導引/射後不理的 `ARMING` 軌跡修正期內。稽核 `audit_weapon_gate.mjs`。
- 射程閘門容差:客戶端的彈道上限是 `range × _altRangeMul × 重砲窗`,伺服器每道閘門 MUST 用 `RANGE_TOL`(單一縫)且**收得下這個上限**。落點/爆點類閘門(`heroBurst`)沒有目標實體、算不出高程差 ⇒ MUST 乘 `altRangeMax()` 當誠實界;寫成比客戶端緊(前科:獨自寫死 1.15)= 高地上合法的那一發被驗證後靜默丟棄,畫面上砲彈在敵人身上炸開、傷害是 0。
- 巨砲(重砲模式;2026-07-30 使用者需求「不消耗一般重武器的彈夾、100% 傷害」改制):這一輪的砲彈是**獨立資源**,不是彈夾裡的子彈 —— 免彈夾/電力/射速/裝填閘,傷害不再有任何倍率;等值性(三招同預算)改由**發數** `barrageShots()` 承擔。三個無聲寫壞法:①只看時間窗判「這發算不算巨砲」⇒ 窗內免彈免電 = 無限開火,整輪傷害隨幀率浮動(唯一判據 MUST 是窗 **且** 發數未打完:伺服器 `_barragingDmg`、客戶端 `_barragingShot()`);②`_heroDmg` 留著任一重砲倍率 ⇒ 不是 100% 傷害,預算被重複計一次;③開窗長度寫死 0.5s ⇒ 發數多的重武器在低幀率打不完,沒打出的發數 = 靜默少掉的預算(MUST 走 `barrageDur(發數)`)。拋射落點判定仍用免除窗(`barrageDur`+`DMG_GRACE`)而非 `_barraging`(彈體飛行期窗會過期);窗內 MUST 免持左鍵自動擊發;客戶端存本地 CD 時戳(防在途舊快照把 CD 洗回 0)。彈夾狀態**刻意不再是前置條件**(空夾/裝填中正是最需要巨砲的時候),`_launchBarrage`/`heroBarrage` MUST NOT 復辟那道閘。
- 飛行動力學(2026-07-30 使用者需求;唯一縫 `data.js FLIGHT` + `airSinkM`/`liftMax`/`liftRegen`/`liftDrainPS`,消費端 `game.js _airSinkHit`/`_stepLift`):①**受擊掉高**入帳掛在「快照偵測到掉血」那一處(與受傷暈影 `hud.hurt` 同一個縫,傷害量 = `_prevVital − vital`),只記帳、逐幀以「待落總量 / `SINK_S`」消化 ⇒ **總掉幅只由傷害決定**(8Hz 快照直接扣 y 是瞬移;做成固定速度則同一份傷害分幾發打完會掉不一樣多)。陣亡/重生/換座機/觸地地面型四處 MUST 清帳,否則舊帳把新機體往下拉。②**爬升動力**只在 `_stepLift` 消耗與回充,且 MUST 排在速度積分**之前**(晚一步就是「先飛上去再扣動力」);見底 MUST 只把 `target.y` 歸零(水平分量不動)—— 改成整體減速就與坡度阻擋 `slopeBlocked` 的語意分家,玩家分不出「爬不上去」與「變慢」。兩者的驅動量(傷害、`maxMp`/`mpRegen`)都是伺服器權威快照,客戶端 MUST NOT 自算;規則只作用於**玩家操控**的飛行機體(`_flying()`)—— bot 沒有客戶端,它那半的掉高住 `sim._botAirSink()`(同一支 `airSinkM`;真人 MUST NOT 在伺服器再套一次,兩套會打架),NPC 直升機/餌機/自殺機是伺服器腳本航線,套上去會陷進地形。稽核 `audit_flight_power.mjs`。
