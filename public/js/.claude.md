## 2. 模組級地雷(依領域;全域 A 表/縫索引已覆蓋者不重複)

### A. 權威結算與戰鬥(sim / data / game)

- 單機序列化:`_serializeEnt` MUST NOT 洩漏權威可變物件的參考(巢狀欄位一律展開複製,如 `o.up = {...e.upg}`)—— 單機傳輸層不經 JSON 深拷貝,客戶端樂觀更新會就地改到伺服器狀態(雙重遞增)。
- 塗層阻擋(A6b)入口三層:`_terrainSegT`(地形,唯一走 `rayTerrain`)→ `_obstHitT`(障礙盒/圓柱 ∪ 橋面/天花/**路面**薄板)→ `_layerHitT`(兩者取近)。表現層彈體 `_updateVisShells` 與榴彈虛線 `_arcTrace` MUST 吃 `_layerHitT`;`_updateBullets`/`_resolveAim` 自己併 `_terrainHitT` + `_obstHitT`(需要分辨 hit.terrain)。`_slabHitT` 的 `!tn.open` 閘同時管天花與路面。爆點回報(`t:'burst'`)洞內的離地基準 = `btn.floor`(heightAt 是未開挖的山頂),但 `lev` 刻意只報 0/2(橋面報 1 = 橋上砲塔 AoE 免傷)。
- 貫穿:首個目標 MUST 全額(bal 不變式);`ARMING` 最短距離內導引 MUST NOT 接手、`b.oy` 擊發當下取樣;bot 的 line 分支吃加粗但射線長維持 bot 自己的射程判定。
- 榴彈:最小射程唯一縫 `lobMinRange(def)`(爆風半徑推導),過近自損由 `blastFalloff` 導出,MUST NOT 另寫公式。火控解與彈道積分收在 `_lobLadder` / `_arcTrace(…, draw)` 兩支:繪製走 draw=true(寫 `_arcGuide` 緩衝)、射程光暈的可命中判定走 draw=false ⇒ **判定端 MUST NOT 自己寫一份簡化積分**(那正是「光暈亮著卻沒命中」的成因)。對空越障仍走 `LOB_CHARGE` 降裝藥(同初速高角解 = 85°、飛 20 秒,MUST NOT 改用)。
- 榴彈投擲改制(2026-08-02 使用者定案四條),四個各自無聲的寫壞法:
  - ①**目標以準星優先**:目標解只有 `_lobCrosshair` 一份(`_updateAaMode` 判要不要進彈射模式、`_lobAim` 取瞄準點,同一幀同吃;它同時是那份「鏡頭/槍口沒動就沿用上一幀」的射線快取 —— 每幀 `_resolveAim` 是 3.7ms 熱點)。錐形輔助 `_aaTarget` 降級成**準星什麼都沒解到**時才接手;舊制無條件吃 8° 錐內最正對的飛行單位 ⇒ 準星明明壓在地面敵人身上,瞄準點還是被拉到旁邊的無人機,而 `_aimTarget` 對 lob 直接吃火控解 ⇒ **鎖定跟著一起被拉走**(使用者回報)。兩端各打一條射線 = 模式判成對地、瞄準點卻鎖在飛機上。
  - ②**對地固定 45°**:角度定死、**初速反解**(`_lob45Vel`:`v0² = g·L²/(L−dy)`),落點恆為準星那個部位。45° 同時是最大射程角與 dy=0 的最小能量解 ⇒ 弧線恆高於同初速低伸解,越障能力本來就優於舊階梯任一級,階梯因此對地面整組讓位(**MUST NOT 兩套並存**)。`L ≤ dy`(目標仰角 ≥ 45°,懸崖正上方)無解 ⇒ 退回階梯,低伸解的仰角本來就比 45° 更陡 = 同一條曲線的延伸,MUST NOT 改成「打不到」。
  - ③**對空維持現狀**:`aa` 旗標 MUST 一路傳進 `_lobLadder`(`_lobAim` 傳 `fc.aa`、`_reachable` 傳 `TARGET_CLASS==='air'`)—— 漏傳就是光暈拿另一條彈道回答火控解的問題。
  - ④**中途碰撞就爆、目標移開就續飛、出射程原地爆**(見下一條的球面規則)。另:45° 解把初速反解到只剩 41~46m/s,`ARC_MAXP` MUST 收得下整段飛行(384 點 ≈ 11.5s;舊 264 會在落地前用光緩衝 ⇒ 打山谷下方的敵人光暈永遠不亮)。`_spawnVisShell` 的對地弧 MUST 同吃 `_lob45Vel`,否則同一個落點兩端畫出兩條不同的弧。
- **射程 = 以射擊點為中心的球面,與軌跡無關**(2026-08-02 使用者定案;唯一一把尺 `|彈頭 − 發射點| ≥ b.max`,四個消費端 `_updateBullets` / `_arcTrace` / `_updateVisShells` / 解保險 `ARMING` 全吃):弧長、導引修正航跡、離架散布繞的路一律不計。**航跡長 `b.dist` 已整組退場**,連同逐彈道分支旗標(`b.seek`/`b.lob`)—— 一顆球面管全部,復辟第二把尺就是靜默丟包:①導引彈的航跡恆長於直線(離架散布 + 一路修正)⇒ 打射程邊緣的目標必定在飛到之前自毀(實測微型攔截彈滿射程恆差 5.5m);②45° 弧長恆為水平距離的 1.148 倍 ⇒ 射程無聲砍 13%、砲彈在抵達瞄準點之前半空自爆。這條同時把其餘三處對齊成同一個球:失鎖判定、伺服器 `heroBurst` 落點閘門 `dist2d(射手, 落點)`、射程光暈 `from.distanceTo(aim)`;唯一例外 = 射後不理**鎖定後**改吃追擊燃料(A7)。**雷射導引吃同一條規則**:導引點出球面只是 `b.guide = false`(不再修正航向、改吃重力直飛),MUST NOT 在那裡把彈體收掉 —— 它照樣飛到球面才原地爆。**這顆球是遊戲空間的正球**(使用者定案):x/z/y 同一個單位、三軸等權,`game.js` 全檔不得出現 `REAL_SCALE`/`COMBAT_SCALE`(前者只住 `terrain.llToWorld`/`sim.llToMeters` 的經緯度邊界、後者只住 `data.js` 統一縮放塊)。遊戲高程走**真實公尺**而水平吃 `1/REAL_SCALE` ⇒ 地形看起來比真實平緩約兩倍,這是刻意的**地形**設計,MUST NOT 拿它當理由在射程的 y 軸乘補正(球面一變橢球,伺服器就與客戶端那顆正球分家)。稽核 `audit_weapon_gate.mjs` Ⅻ⑷ 以「同一段距離擺水平與擺垂直同判」行為直測釘住。
- 射程光暈(2026-07-30 使用者回報「榴彈類常常光暈亮著卻沒命中對方」):語意是**打得到**,不是距離夠近。判據唯一縫 = `data.js reachRule()` → `game.js _reachable()`,逐彈道五類分派 —— 拋物線跑火控階梯、直線跑 `_layerHitT` 線段;爆炸戰鬥部看「落點是否落在 `blastCoreR` 核心帶內」(**刻意不要求 LOS**:爆風不吃 LOS,A11 繞射近似 ⇒ 貼著掩體炸開照樣亮),直擊/貫穿看「線段整段淨空」(對齊伺服器 `_losBlocked`)。三個無聲寫壞法:①退回只量距離(回到原病灶);②在光暈那邊多加 `if (def.type…)`(第二份分類表 = 與 `trajClass` 分家);③每幀替全場敵人重算彈道積分(把 `_lobAim` 熱路徑乘上敵人數)—— 節流走 `RANGE_GLOW`(每幀固定枚數 + TTL 快取 + 換武器/重砲窗整批作廢),**尚未評估過的目標不亮**(寧缺勿錯)。警示色(琥珀)= 打得到但命中率低/會自損:榴彈最小安全射程內、導引/射後不理的 `ARMING` 軌跡修正期內。稽核 `audit_weapon_gate.mjs`。
